Frontmatter keys are the columns. A record whose file is missing the key does not match a
comparison against it.

## Finding one record

```php
Post::find('hello-world');                  // ?Post
Post::findOrFail('hello-world');            // throws ModelNotFoundException
Post::findOr('hello-world', fn () => null); // runs the callback when missing
Post::findMany(['hello-world', 'about']);   // Collection

Post::where('published', true)->first();
Post::where('published', true)->firstOrFail();
Post::where('published', true)->sole();     // exactly one, or it throws
Post::firstWhere('title', 'Hello World');
Post::where('published', true)->value('title');
```

`find` also applies the constraints already on the query:

```php
Post::where('published', true)->find('draft-post'); // null
```

## Constraints

| Method                              | Matches                                                                       |
| ----------------------------------- | ----------------------------------------------------------------------------- |
| `where($column, $value)`            | Equality, compared loosely                                                    |
| `where($column, $operator, $value)` | `=`, `==`, `===`, `!=`, `<>`, `!==`, `>`, `>=`, `<`, `<=`, `like`, `not like` |
| `whereIn` / `whereNotIn`            | Membership in a list of values                                                |
| `whereNull` / `whereNotNull`        | A missing or null key                                                         |
| `whereBetween` / `whereNotBetween`  | An inclusive range, bounds read by position                                   |
| `whereContains`                     | A value inside an array field                                                 |
| `whereLike` / `whereNotLike`        | A `%` pattern, case insensitive by default                                    |
| `whereAny` / `whereAll`             | One constraint across several columns                                         |
| `whereRegexp` / `whereNotRegexp`    | A regular expression                                                          |
| `whereColumn`                       | One field compared to another                                                 |
| `whereDate` and friends             | One part of a date                                                            |

Each has an `or` counterpart: `orWhere`, `orWhereIn`, `orWhereContains`, and so on.

```php
Post::whereContains('tags', 'laravel')->get();
Post::whereLike('title', '%hello%')->get();
Post::whereNotLike('title', '%draft%')->get();
Post::whereAny(['title', 'content'], 'like', '%flat-file%')->get();
Post::whereBetween('views', [100, 500])->get();
Post::whereRegexp('title', '/^v\d+\./')->get();
Post::whereColumn('sale_price', '<', 'price')->get();
```

A `like` pattern is anchored, so `%` is needed at both ends to match a substring. `_` matches a
single character. Pass `true` as the third argument to `whereLike` for a case-sensitive match.

Operators are case insensitive, so `LIKE` works the same as `like`.

A regex pattern is passed to `preg_match` as is, so it needs its own delimiters. An invalid pattern
throws `InvalidArgumentException` when the query is built, not when it runs.

`whereColumn` needs both fields to be read the same way. Comparing a cast field to one without a
cast throws `InvalidArgumentException`, since the two values would no longer be alike.

## Several conditions at once

Pass an array to `where` or `orWhere`, either as pairs or as `[column, operator, value]`:

```php
Post::where(['published' => true, 'category' => 'guide'])->get();

Post::where([
    ['status', '=', 'active'],
    ['views', '>', 100],
])->get();
```

The conditions are grouped, so `orWhere([...])` works like a closure full of `where` calls.

## Nested frontmatter

Use dot-notation to reach into a nested key:

```yaml
---
title: Hello World
seo:
    title: Hello, flat files
    index: true
---
```

```php
Post::where('seo.index', true)->orderBy('seo.title')->get();
```

It works in `where`, `orderBy` and the aggregates. A top-level key that has a dot in its name
still wins over the nested lookup.

## Dates

`whereDate`, `whereYear`, `whereMonth` and `whereDay` read a frontmatter date and compare one part
of it:

```php
Post::whereDate('date', '2026-09-25')->get();
Post::whereDate('date', '>=', now()->subMonth())->get();
Post::whereYear('date', 2026)->whereMonth('date', '<', 7)->get();
```

The value can be a string or any `DateTimeInterface`. A record whose date is missing or cannot
be parsed does not match.

## Grouping and precedence

`and` binds tighter than `or`, the way it does in SQL. Pass a closure to group a set of
constraints:

```php
Post::where('published', true)
    ->where(function ($query) {
        $query->where('featured', true)
            ->orWhere('pinned', true);
    })
    ->get();
```

Comparing a column to `null` checks for null rather than matching nothing:

```php
Post::where('reviewed_at', null)->get(); // same as whereNull('reviewed_at')
```

## Ordering and limits

```php
Post::orderBy('date', 'desc')->get();
Post::orderByDesc('date')->get();
Post::latest('date')->get();
Post::oldest('date')->get();
Post::inRandomOrder()->first();

Post::limit(10)->offset(20)->get(); // take() and skip() are aliases
```

Multiple `orderBy` calls behave like SQL: the first column is primary, the rest are tiebreakers. A
query with no order comes back in a stable slug order.

## Conditional constraints

```php
Post::query()
    ->when($request->tag, fn ($query, $tag) => $query->whereContains('tags', $tag))
    ->unless($request->user(), fn ($query) => $query->where('published', true))
    ->get();
```

## Counting and aggregates

```php
Post::count();
Post::where('published', true)->exists();
Post::where('draft', true)->doesntExist();

Post::max('order');
Post::min('order');
Post::where('published', true)->sum('views');
Post::avg('rating'); // average() is an alias
```

Null, missing and non-numeric values are skipped, the way SQL aggregates skip `NULL`. On an empty
result `sum` returns `0` and the others return `null`.

`countBy` tallies each distinct value of a column, in the order the values first appear:

```php
Post::countBy('category');                       // ['guide' => 2, 'archive' => 1]
Post::where('published', true)->countBy('tags'); // ['laravel' => 2, 'php' => 1]
```

Each item in an array field like `tags` is counted, and null, missing or nested values are skipped.

## Plucking values

```php
Post::pluck('title');         // Collection of titles
Post::pluck('title', 'slug'); // keyed by slug
```

## Scopes

Scopes work as they do on any model, including methods marked with Laravel's `#[Scope]` attribute:

```php
use Illuminate\Database\Eloquent\Attributes\Scope;

class Post extends Model
{
    use Paper;

    #[Scope]
    protected function published($query)
    {
        return $query->where('published', true);
    }
}

Post::published()->latest('date')->get();
```

## Global scopes

A global scope applies to every query on the model, including `find` and route model binding.
Register a closure in `booted`:

```php
protected static function booted(): void
{
    static::addGlobalScope('published', fn ($query) => $query->where('published', true));
}
```

For a scope class, implement `ScopeContract` rather than Eloquent's `Scope`. A Paper query is not
an Eloquent builder, so `apply` gets a `PaperQueryBuilder`:

```php
use Illuminate\Database\Eloquent\Model;
use JacobJoergensen\LaravelPaper\Contracts\ScopeContract;
use JacobJoergensen\LaravelPaper\PaperQueryBuilder;

class PublishedScope implements ScopeContract
{
    public function apply(PaperQueryBuilder $query, Model $model): void
    {
        $query->where('published', true);
    }
}
```

Add it with `addGlobalScope(new PublishedScope)`, or with Laravel's `#[ScopedBy]` attribute:

```php
use Illuminate\Database\Eloquent\Attributes\ScopedBy;

#[ScopedBy(PublishedScope::class)]
class Post extends Model
{
    use Paper;
}
```

To leave a scope out of one query:

```php
Post::withoutGlobalScope(PublishedScope::class)->get();
Post::withoutGlobalScope('published')->get();
Post::withoutGlobalScopes()->get();
```

`fresh`, `refresh` and the `PaperRule` validation rules ignore global scopes, the same way
Eloquent does.

<Callout label="note">
    `get` builds a model for every match at once. For a directory with thousands of files, walk it with `lazy`, `chunk`
    or `each` instead. See [Pagination and large sets](/docs/pagination).
</Callout>
